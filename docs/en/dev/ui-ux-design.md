# klaus UI Visual / UX Design (M4)

> [!summary] Role of this document
> While [[ui-design]](ui-design.md) defines the architecture (server / API / security), this document defines the **direction** for visual design and UX.
>
> **The implementation details (actual token values, component composition) are authoritative in [`ui/docs/design-system.md`](https://github.com/almondoo/klaus/blob/main/ui/docs/design-system.md) and [`ui/docs/components.md`](https://github.com/almondoo/klaus/blob/main/ui/docs/components.md)**. The UI is implemented with shadcn/ui + Tailwind CSS v4, and the actual CSS variables live in `ui/src/styles/globals.css`. Where this document and the implementation disagree, the implementation is correct (see "Differences from the implementation" below).
>
> `docs/dev/design-system/klaus/MASTER.md` is a starting point generated by ui-ux-pro-max, and the current implementation intentionally deviates from it in places.

## Design direction

A search of ui-ux-pro-max products matched "Developer Tool / IDE": **Dark Mode (OLED) + Minimalism**, with a dashboard style of **Real-Time Monitor + Terminal**. Of the generated MASTER.md, the elements aimed at landing pages (the Minimal Single Column pattern, the oversized `clamp(3rem 10vw 12rem)` heading) are **not applied to the app UI** (they are recommendations for marketing pages and do not fit a runner UI). What is adopted are the color, typography, density, and motion tokens.

- **Dark mode as the default** (per the DB anti-pattern "Light mode default"). Light mode is deferred to a future phase and is not built in the initial implementation
- Terminal-like information density: density 8/10 (spacing scale 8-32px). Don't decorate with whitespace; make execution results highly scannable
- Motion is subtle (2/10). GSAP is not introduced; CSS transitions (150-300ms) suffice for the scope needed (keeping the dependency footprint of a global CLI from growing; the GSAP snippet in MASTER.md is unused). `prefers-reduced-motion` is respected

## Color direction

The palette is "code-editor-style dark + status colors". The actual CSS variable names and values are authoritative in `ui/src/styles/globals.css`, with a mapping table in [`ui/docs/design-system.md`](https://github.com/almondoo/klaus/blob/main/ui/docs/design-system.md). Reference colors as a matter of direction:

| Role | Hex | Usage |
|------|-----|------|
| Background | `#020617` | App background |
| Foreground | `#F8FAFC` | Base text |
| Surface (dark) | `#0F172A` | Header, sidebar |
| Surface (light) | `#1E293B` | Cards, panels |
| Border | `#334155` | Boundaries |

Status colors (in the implementation: `--pass` / `--fail` / `--running` / `--skipped` / `--pending`):

| State | Hex | Notes |
|------|-----|------|
| pass | `#22C55E` | Also shared with the run button (`--primary`) |
| fail | `#EF4444` | Shared with `--destructive` |
| running | `#38BDF8` | sky. Spinner / in-progress. Also used for the focus ring (`--ring`) |
| skipped | `#F59E0B` | amber. Steps skipped after a flow aborts |
| pending | `#94A3B8` | Not yet run. Shared with `--muted-foreground` |

**Never let color alone carry meaning** (a required accessibility rule): pass/fail/skipped must always be accompanied by an icon plus a text label. Maintain contrast of at least 4.5:1.

### Differences from the implementation (the implementation is authoritative)

In migrating to shadcn/ui, the following were intentionally changed from the initial proposal in this document and MASTER.md:

- **Icons are lucide-react** (the shadcn standard). The originally proposed Phosphor Icons were dropped
- **Color role names are remapped to shadcn's semantics**. `#0F172A` is a surface color, so it maps to `--popover`; the actual action color `#22C55E` becomes `--primary`
- **`--ring` is `#38BDF8` (sky)**. MASTER.md assigned navy (`#0F172A`) to `--ring`, but that was corrected because a focus ring is barely visible against the `#020617` background
- **Spacing uses the Tailwind standard scale**. MASTER.md's `--space-xs` through `--space-3xl` are not implemented
- **Light mode is unimplemented**. `:root` and `.dark` are identical, with `<html class="dark">` fixed

## Typography

- **Heading / data (URLs, paths, status codes, durations, JSONPath): Fira Code** (monospace, the core of the terminal-like feel)
- **Body (descriptions, labels): Fira Sans**
- Base 16px, line-height 1.5. Table data is allowed down to 14px (below 12px is prohibited)
- Fonts are bundled via **npm packages (@fontsource/fira-code, @fontsource/fira-sans)** rather than the Google Fonts CDN (the localhost UI should work offline; a dependency on an external CDN is also inconsistent with the same-origin policy)

## Application per screen (corresponding to the three screens in [[ui-design]])

### 1. Flow list (sidebar)
- Fixed left sidebar (240-280px) + a two-pane main area. Mobile support is low priority (it's a local developer tool), but the sidebar becomes a drawer at 768px
- Flow names in Fira Sans, file paths in muted Fira Code
- Flows with a parse error show a Destructive icon plus a tooltip explaining the reason in the list
- The environment selector and run button are fixed to the top of the main area

### 2. Run view (Real-Time Monitor)
- Steps are shown as a vertical list, transitioning `running -> pass/fail` via SSE progress. **Any wait exceeding 300ms must show an indicator** (a running spinner) (UX DB: Loading Indicators / High)
- Overall progress uses a "Step 2 / 5" style step indicator (UX DB: Progress Indicators)
- Failed steps expand the row to show request/response details (Fira Code, JSON with syntax highlighting). Successful steps are collapsed by default — carrying the CLI's "one-line summary on success" philosophy over into the UI
- The run button enters a loading state immediately on press, and shows a success/failure summary on completion (UX DB: Submit Feedback / High)

### 3. History browser
- A newest-first table (density 8/10: row height 32-36px, muted striped background). Pagination uses a `before` cursor for lazy loading (UX DB: Lazy Loading — never preload everything)
- Grouped by run, with drill-down into step details

## Icons

- **Unified on lucide-react** (the shadcn standard icon library). Emoji are never used as icons (a required rule)
- Primary mappings: run = Play, pass = CheckCircle, fail = XCircle, skipped = MinusCircle, running = Loader2 (spinning), history = History, back = ArrowLeft. See [`ui/docs/components.md`](https://github.com/almondoo/klaus/blob/main/ui/docs/components.md) for the icons actually in use
- Icon-only buttons must always have an `aria-label`. Ensure a click target of at least 44x44px

## React implementation rules (from stack search)

- Use stable IDs for list keys (`runId`, step name within a flow). Index keys are prohibited (Severity: High)
- Do not hold derived values (pass count, total time, etc.) in state; compute them during render (Severity: High)
- Use `useState(() => ...)` lazy initialization for expensive initial values such as parsing the history JSONL
- State management starts with React's standard tools (as per the [[ui-design]] direction)

## Accessibility / quality checklist (completion criteria)

- [ ] Text contrast of at least 4.5:1 (also verify muted text against the dark background `#020617`)
- [ ] Keyboard-operable (from selecting a flow -> running -> expanding results), focus ring not removed
- [ ] pass/fail distinguishable via a triple signal: color + icon + text
- [ ] Clickable elements have cursor-pointer and a 150-300ms hover transition
- [ ] All animation other than the spinner stops under `prefers-reduced-motion`
- [ ] No horizontal scroll at 375px / 768px / 1024px / 1440px (only the JSON detail block may scroll internally)
